# تأسيس قاعدة سعي

نفّذي محتوى migrations/202610060001_catalog.sql مرة واحدة في SQL Editor، بدور postgres.
ينشئ جدولَي المحتوى opportunities وproviders (جهات التعلم)، وأربعة جداول للمجالات والأنواع وربطها بالمحتوى، وفق doc/RELEASE-1.md.
لا يحذف شيئًا، ولا ينقل أمثلة الواجهة إلى قاعدة البيانات. إذا كان أحد الأسماء موجودًا يتوقف التنفيذ وتُلغى المعاملة؛ لا تحذفي الجدول لمعالجة الخطأ دون مراجعة.

الزائر والمستخدم المسجل يقرآن المنشور فقط؛ الفرص ذات الموعد الدقيق المنقضي غير متاحة للقراءة العامة. لا كتابة عبر واجهة الموقع في هذه المرحلة. الإدارة من لوحة Supabase. لا تُكشف created_by للقراء؛ يجب أن يحدد محول الواجهة الأعمدة المسموحة صراحة بدل select(*).

هذه نسخة أولى لم تُطبّق أو تُختبر على المشروع البعيد بعد. إنشاء الجداول لا يربط الواجهة تلقائيًا. بعد نجاح التنفيذ نختبر صلاحيات القراءة ومنع الكتابة، ثم نضيف محول الربط. الحسابات والمحـفوظات والتجارب مرحلة تالية. الفرعان يشتركان في قاعدة واحدة؛ تطبق كل migration مرة واحدة بواسطة مسؤول الأساس.


## تحديث الربط — 6 أكتوبر 2026

تم ربط قراءة الفرص وجهات التعلم بمشروع Supabase الحالي عبر catalog-client.js وcatalog-service.js. تحويل بيانات كل قسم مستقل في features/opportunities/service.js وfeatures/learning/service.js. يستخدم الاتصال مفتاح publishable العام فقط. لا تُستخدم أمثلة الملفات عند فشل الاتصال؛ تظهر حالة الخطأ وإعادة المحاولة. الجدولان فارغان حاليًا، والتجارب تعاد قائمة فارغة حتى ربط خدمتها. لم تُربط المصادقة أو المحفوظات أو إرسال التجارب أو إدارة المحتوى من الواجهة؛ الإدارة حاليًا من Supabase.

نجح اختبار القراءة الحقيقي والمحولات داخل المتصفح، ورُفضت محاولة إدخال فارغة بالمفتاح العام وقراءة created_by. اختبارات الرحلات تستخدم مصدرًا تجريبيًا صريحًا، ولا تنشئ بيانات طلاب في القاعدة. اختبار رؤية مسودة مقابل منشور بحساب طالب ينتظر إضافة بيانات اختبار وربط الحسابات؛ لا يعد الربط الحالي اعتمادًا للإطلاق.
